# Доступ в админку по почте

Админка живёт по адресу `/admin`. Пароля нет: редактор вводит рабочую
почту, получает письмо со ссылкой и по ней входит. Доступ выдаёт школа —
заводит адрес в списке пользователей; по чужой почте письмо не придёт.

Сайт статический и лежит на GitHub Pages: своего сервера у него нет,
поэтому письма и проверку входа берёт на себя Supabase (бесплатный
тариф). Там же хранится ключ публикации — в браузер редактора он
не попадает.

## Что нужно сделать один раз

### 1. Завести проект

1. Зарегистрироваться на supabase.com и создать проект (регион — ближе
   к Москве, например Frankfurt).
2. Settings → API: скопировать **Project URL** и **anon public key**.
   Это публичные значения, их видно в браузере — так и задумано.

### 2. Прописать ключи в сборку сайта

GitHub → репозиторий → Settings → Secrets and variables → Actions →
вкладка **Variables** → New repository variable:

| Имя | Значение |
|-----|----------|
| `SUPABASE_URL` | Project URL |
| `SUPABASE_ANON_KEY` | anon public key |

После этого сайт пересоберётся, и на `/admin` появится вход по почте.
Пока переменных нет, админка открывается сразу — как сейчас.

### 3. Закрыть самостоятельную регистрацию

Supabase → Authentication → Providers → Email:

- **Confirm email** — включено;
- **Allow new users to sign up** — выключено.

Так войти сможет только тот, кого завели вручную.

### 4. Разрешить возврат на сайт

Authentication → URL Configuration:

- **Site URL**: адрес сайта, например `https://schooldmitrovsky.ru`;
- **Redirect URLs**: добавить `https://schooldmitrovsky.ru/admin`
  и адрес превью на GitHub Pages, если им пользуются.

### 5. Выдать доступ редактору

Authentication → Users → **Add user** → Send invitation. Человек получит
письмо, перейдёт по ссылке и попадёт в админку. Чтобы забрать доступ —
удалить пользователя там же.

### 6. Развернуть публикацию

Функция публикации лежит в `supabase/functions/publish`. Разворачивается
из папки проекта:

```
npx supabase login
npx supabase link --project-ref <ref из адреса проекта>
npx supabase functions deploy publish --no-verify-jwt
npx supabase secrets set \
  GITHUB_TOKEN=<ключ GitHub> \
  ADMIN_EMAILS=<почты через запятую> \
  SITE_ORIGIN=https://schooldmitrovsky.ru
```

Ключ GitHub создаётся в GitHub → Settings → Developer settings →
Personal access tokens → Fine-grained: доступ только к репозиторию
`-school_dmitrovsky`, право **Contents: Read and write**.

## Как это работает

1. Редактор открывает `/admin`, вводит почту, получает письмо.
2. По ссылке возвращается на `/admin` уже опознанным; ключи входа
   стираются из адреса, чтобы не осели в истории браузера.
3. Правит материалы, видит превью карточки и жмёт «Опубликовать».
4. Браузер обращается к функции `publish`, та проверяет вход и адрес,
   кладёт файлы разделов в ветку сборки, и сайт пересобирается сам.

Функция принимает только четыре файла — `clubs.json`, `news.json`,
`teachers.json`, `reviews.json` — и отказывает, если в них не JSON.
Ничего другого через админку записать нельзя.

## Пока вход не настроен

Админка открыта и публикует по ключу, который редактор один раз
вставляет в поле «Ключ доступа». Ключ лежит только в его браузере;
на чужом компьютере после работы нужно нажать «Забыть».
