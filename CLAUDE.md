# CLAUDE.md

Проект: редизайн сайта ГБОУ Школа «Дмитровский» (schooldmitrovsky.ru).

## Контекст проекта

Этап 1 — полный визуальный и UX-редизайн с сохранением всего текущего
наполнения. Правила переноса зафиксированы в техническом задании
(`source/FULL_TZ_schooldmitrovsky_Claude_Code.docx`) и в документах:

- `INVENTORY_CHECK.md` — отчёт по материалам выгрузки;
- `QUESTIONS.md` — спорные элементы и блокирующие вопросы;
- `FUTURE_IMPROVEMENTS.md` — всё, что выходит за рамки этапа 1;
- `docs/ASSETS_AUDIT.md` — разбор изображений.

Стек: Next.js 16 (App Router), React 19, TypeScript strict, CSS Modules
на единых токенах (`src/styles/tokens.css`).

Команды: `npm run build`, `npm run typecheck`, `npm run lint`,
`npm run check:content`, `npm run build:pages`.

Проверки собранного сайта (сначала `npm run build:preview`):

- `npm run check:layout` — 22 страницы на 390, 768, 1280 и 1440 px:
  горизонтальный скролл, выход за экран, битые изображения, область
  нажатия 44 px, ровно один H1. С `--shots dir` сохраняет скриншоты.
- `npm run check:text` — все строки выгрузки на месте. Внутренние страницы
  собираются композициями, а не сплошным потоком блоков, поэтому нужна
  проверка, что при перекладке ничего не потерялось (ТЗ §7).

## Website workflow and skills

### Перед началом

- Перед созданием или редизайном сайта изучить текущий проект, контент,
  изображения и технические ограничения.
- Не заменять реальные тексты и изображения заглушками, если пользователь
  этого не просил. Фактический контент живёт в `src/content/`,
  оригиналы материалов — в `source/`.

### Какой skill под какую задачу

| Задача | Skills |
|---|---|
| Визуальная концепция, UI, компоненты | `frontend-design`, `ui-ux-pro-max` |
| Дизайн-система, токены, темы | `brand-guidelines`, `theme-factory` |
| Сложные интерактивные страницы | `web-artifacts-builder` |
| Лендинги | `landing-page-generator` + `copywriting` + `page-cro` совместно |
| SEO | `seo-audit`; для массовых SEO-страниц — `programmatic-seo` |
| Цели, события, формы, воронки | `analytics-tracking` |
| Доступность и тестирование интерфейса | `a11y-audit`, `webapp-testing` |
| Разбор ошибок | `systematic-debugging` |
| Проверка перед сдачей | `verification-before-completion` |

### Правила применения

- Не активировать все skills одновременно: выбирать минимальный набор
  под текущую задачу.
- До завершения работы над интерфейсом выполнять `a11y-audit`
  и `webapp-testing`.
- При ошибках применять `systematic-debugging` вместо точечных догадок.
- Перед сообщением о готовности обязательно применять
  `verification-before-completion`: проверить сборку, ошибки,
  ключевые ссылки, формы, мобильные разрешения и отсутствие явных
  визуальных дефектов.

### Обязательная проверка перед словом «готово»

1. `npm run typecheck` — без ошибок.
2. `npm run lint` — без ошибок.
3. `npm run build` — сборка проходит.
4. `npm run check:layout` — 390, 768, 1280 и 1440 px: нет горизонтального
   скролла, наложений, обрезанных кнопок и битых изображений; на каждой
   странице ровно один H1.
5. `npm run check:text` — ни одна строка выгрузки не потерялась.
6. Внутренние ссылки меню и подвала не отдают 404.

Пункт 4 закрывается прогоном проверки, а не предположением. Скриншоты
(`--shots`) смотреть глазами: автопроверка ловит переполнение и битые
файлы, но не кривую композицию.

Изменив данные, от которых зависит страница, открыть эту страницу заново.

### Композиции страниц

Внутренние страницы собираются не сплошным потоком блоков, а по типам
полос Tilda (`src/content/compositions.ts`): тарифы и перечни — карточками,
вопросы родителей — аккордеоном, педагоги — сеткой, каталог мерча —
карточками товара, полоса набора — блоком с ценой и составом программы.

Добавляя композицию, помнить: тексты, их порядок и состав не меняются
(ТЗ §7). Любой блок, который перестал выводиться, — это решение, а не
недосмотр: его нужно занести в `QUESTIONS.md` и в список исключений
`scripts/check-text-coverage.mjs`, иначе проверка не пройдёт.

### Имена skills, которые совпадают

`brand-guidelines` есть и в `example-skills`, и в `marketing-skills`.
Для дизайн-системы использовать версию из `example-skills`
(Anthropic) — она про визуальные токены; версия из `marketing-skills`
про маркетинговый бренд-гайд.
